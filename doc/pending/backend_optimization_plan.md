# 后端优化方案：安全与性能 (评估报告)

这份文档概述了针对 Go 后端的进一步优化方案，并结合当前系统现状对其 **必要程度** 和 **可行性** 进行了深度评估。

## 2. 安全性优化 (Security)

### 2.1 强制密码策略

- **当前状态**: 仅有简单长度校验，甚至默认密码过于简单（同用户名）。
- **评估**:
  - **必要性 (高)**: 防止弱口令通过爆破手段攻破。
  - **可行性 (高)**: 后端增加正则校验函数，前端增加 UI 提示。

### 2.2 审计日志增强 (Location/Device)

- **优化建议**: 记录用户登录时的 `User-Agent`、`IP` 及解析出的地理位置。
- **评估**:
  - **必要性 (中)**: 用于异地登录检测和安全溯源。
  - **可行性 (高)**: 引入开源 GeoIP 库即可实现。

### 2.3 鉴权体系升级 (Casbin)

- **优化建议**: 引入 Casbin 实现 RBAC/ABAC。
- **评估**:
  - **必要性 (中)**: 当前自定义权限系统能满足业务，大规模角色扩展时才显必要感。
  - **可行性 (中)**: 需要重写中间件和权限数据库表结构。

## 3. 性能与工程化优化 (Performance & Engineering)

### 3.1 代码模块化重构 (Code Splitting)

- **优化建议**: 将 `internal/controller/extended_controller.go`（超过 1200 行）按模块拆分为 `student_controller.go`, `teacher_controller.go` 等。
- **评估**:
  - **必要性 (高)**: 降低代码维护难度，减少合并冲突风险。
  - **可行性 (高)**: 纯代码重构，不涉及业务改动。

### 3.2 结构化日志 (Structured Logging)

- **优化建议**: 使用 `Zap`。输出 JSON 格式日志，支持不同级别（Debug, Info, Warn, Error）。
- **评估**:
  - **必要性 (高)**: 方便结合日志收集系统进行监控和告警。
  - **可行性 (高)**: 替换现有的 `log.Printf` 即可。

### 3.3 输入参数校验 (Validator)

- **优化建议**: 引入 `go-playground/validator`。
- **评估**:
  - **必要性 (高)**: 提高代码健壮性，减少由于脏数据导致的系统 panic。
  - **可行性 (高)**: 通过 Struct Tag 实现，代码改动点清晰。

## 4. 实施阶段规划 (Priority)

### 第一阶段：工程化与健壮性 (立即实施)

1. **代码重构**: 拆分 `extended_controller.go` 和 `main.go`。
2. **结构化日志**: 全面接入 `Zap` 记录系统关键路径。
3. **输入校验**: 在创建学生、教工的核心接口应用 `validator`。

### 第二阶段：安全防御与性能 (两周内)

1. **密码策略**: 后端实现强制复杂度检查，增强 `ResetPassword` 安全。
2. **连接池与索引**: 定期检查 `EXPLAIN`，优化慢查询索引。
3. **Redis 缓存扩展**: 对楼宇和角色列表实现 Cache-Aside 模式。

### 第三阶段：合规与进阶 (视业务需求)

1. **审计增强**: 记录详细的登录上下文信息（地理位置、浏览器标识）。
2. **Argon2id**: 在对安全性要求极高的环境下替换 bcrypt。

## 5. 已完成优化项

- ✅ Access Token 登出后立即失效
- ✅ Refresh Token 轮转机制

### 5.2 分布式限流 (2025-12-26)

- ✅ 基于 Redis Sorted Set 的滑动窗口算法
- ✅ 登录接口限流：5 分钟内最多 5 次尝试
- 详见: `doc/progress_distributed_ratelimit.md`

### 5.3 关键业务优化 (2025-12-26)

- ✅ **仪表盘性能**: 添加了 60 秒内存缓存。
- ✅ **文件安全**: 实现了 MIME 类型探测和严格大小限制。
- ✅ **批量导入**: 实现了基于事务的 Upsert 逻辑，提升数据导入稳定性。
- ✅ **接口兼容**: 统一了错误码返回结构（`message` 字段对齐）。
