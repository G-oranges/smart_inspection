# 确认弹窗策略规范（Confirm Policy）

文档状态：Active（Phase 3 已更新）
最后更新：2026-11-24
适用范围：全前端系统（桌面端 + 移动端）
目标：在保障不可逆危险操作不被误触的前提下，消除非危险操作的冗余弹窗与重复确认，统一全站确认弹窗的触发规则与文案规范。

---

## 1. 核心原则（Principles）

### P1. 按操作危险度决定是否确认，不再对常规写操作弹窗
- **非危险写操作**（新增表单、编辑保存、修改个人联系方式等可逆操作）：用户在表单内点击明确的主动作按钮即表示确认，**直接提交**，禁止再弹二次确认弹窗。
- **敏感但可逆/影响范围明确的操作**（退出登录、重置密码、全局系统设置保存、调宿/互换/单条退宿）：使用**单次普通确认弹窗**。
- **不可逆危险操作**（删除类与批量退宿）：使用**单次倒计时强确认**（`confirmDangerCountdown`），禁止叠加两层弹窗（如 Popconfirm + 倒计时弹窗，或普通 Modal + 倒计时弹窗）。

### P2. 风险等级决定确认形态，而不是页面位置
确认方式不由 UI 形态（桌面表格 / 移动抽屉）决定，只由操作是否不可逆、是否批量、是否影响全局或他人数据决定。移动端 `IOSActionSheet` 只是动作入口菜单，点击危险项后同样触发单次倒计时确认，不在 ActionSheet 内部写确认逻辑。

### P3. 确认弹窗文案规范
- **标题**：直接用问句，说清对象和动作（如 `确定删除楼栋「荟园 1 栋」吗？`），禁止使用 `是否确认 - xxx` 模板前缀。
- **正文**：说清具体会失去什么、是否可恢复（如 `删除后无法恢复，选中的 3 间宿舍及其入住记录都会被清除。`）。
- **按钮**：主按钮必须写具体动作（如 `删除楼栋`、`删除用户`、`确认退宿`），禁止写 `确定` 或问句 `是否确认`。危险操作使用 `danger` 按钮样式，正向操作（如 `确认入住`）使用 `primary` 按钮样式。

---

## 2. 操作风险分级定义（Risk Levels）

### L1｜无风险与常规可逆写操作（直接执行，无需确认）
- 前端态操作：Tab 切换、展开/折叠、筛选、页面跳转。
- 常规可逆写操作：新增/编辑楼栋、宿舍、学生、教职工、用户、角色、查寝任务、查寝记录、修改个人联系方式等（表单主按钮本身即明确提交意图）。
- **规则**：禁止弹出二次确认弹窗；操作完成后使用轻量 toast 反馈（结果已在界面直接可见时可不弹）。

### L2｜敏感影响操作（单次普通 Global Confirm）
- 适用范围：
  - 重置密码 / 生成临时密码
  - 启用 / 停用账号或角色
  - 保存全局系统设置（影响全校评分与扣分规则）
  - 办理调宿 / 互换床位 / 单条退宿 / 批量入住确认
  - 退出登录
- **规则**：使用单次 `Modal.confirm`，无需倒计时。

### L3｜不可逆危险操作（单次 5 秒倒计时强确认）
- 适用范围（全站统一）：
  - 单条 / 批量删除楼栋
  - 单条 / 批量删除宿舍
  - 单条 / 批量删除学生
  - 单条 / 批量删除教职工
  - 单条 / 批量删除用户
  - 单条 / 批量删除查寝任务
  - 单条 / 批量删除查寝记录
  - 批量删除异动历史记录
  - 批量退宿
- **规则**：统一调用 `frontend/src/utils/confirm.ts` 中的 `confirmDangerCountdown`，**仅弹一次**：
  1. 初始状态 `okButtonProps.disabled = true`，按钮显示 `${okText} (5)`。
  2. 每秒刷新剩余秒数，5 秒结束后恢复可点击，按钮文字恢复为具体动作（如 `删除用户`）。
  3. 必须设置 `maskClosable: false`、`keyboard: false`，防止误触遮罩或 ESC 绕过。
  4. `onOk` / `onCancel` / 倒计时结束三处均必须清理定时器。
  5. **禁止**在行内按钮外套 `Popconfirm` 再弹倒计时弹窗，**禁止**在批量操作前先弹普通 `Modal.confirm` 再弹倒计时弹窗。

---

## 3. 明确禁止的行为（Hard Rules）

- 禁止对常规新增/编辑表单提交追加二次确认弹窗。
- 禁止同一删除操作连续触发两次确认（如 `Popconfirm → confirmDangerCountdown` 或 `Modal.confirm → confirmDangerCountdown`）。
- 禁止两个确认 Modal 同时叠加显示。
- 禁止在 `IOSActionSheet` 组件内部直接调用 `Modal.confirm`，确认逻辑统一收口在页面 Action Hook 中。
- 禁止用 `Modal.success` 弹窗代替 toast 播报常规操作成功结果。
- 禁止将正向操作（如批量入住）的确认按钮设为 `danger` 红色样式。
- 禁止使用 `是否确认` 作为按钮文字或标题拼接前缀。
