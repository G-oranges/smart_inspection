## 3. 宿舍页统计卡交互升级

### 3.1 新增可折叠统计板组件

**变更文件**

- `frontend/src/components/stats/CollapsibleStatsBoard.tsx`
- `frontend/src/hooks/useContextualStatsState.ts`
- `frontend/src/styles/components/stats.css`
- `frontend/src/components/PageLayout.tsx`
- `frontend/src/pages/DormManagementPage.tsx`

**完成内容**

- 新增 `CollapsibleStatsBoard`，支持展开态统计卡和折叠态微型统计条之间切换。
- 新增 `useContextualStatsState`，把统计区抽象为 `EXPANDED / COLLAPSED / ARMED / EXPANDING` 状态机。
- `PageLayout` 增加 `statsLayout="custom"`，允许页面注入非默认 `Row` 结构的统计区。
- `DormManagementPage` 去掉原先的手动切换按钮和 `statsCollapsed` 本地状态，改为接入上下文感知统计板。

**交互策略**

- 桌面端：
  - 页面下滚超过阈值后，完整统计卡折叠为顶部 sticky 微型统计条。
  - 回到顶部后进入 `ARMED` 状态，继续向上滚动可触发展开。
- 移动端：
  - 默认使用更轻量的折叠 handle。
  - 到达顶部后下拉可展开统计概览，结束触摸后会回到折叠态。

**解决的问题**

- 原先“展开/收起统计卡片”需要显式点击，打断浏览节奏。
- 完整统计卡在长列表页面里占据较高首屏高度，影响表格区可见面积。
- 移动端如果照搬桌面端微型统计条，会显得拥挤，因此单独做了 handle 化处理。

### 3.2 展示逻辑二次收敛

**对应提交**

- `fe9409d`

**完成内容**

- 将折叠态样式从较重的玻璃拟态进一步收敛为更轻的透明展示逻辑。
- 移动端折叠高度由 `46px` 调整为 `32px` 级别的 handle 区。
- 移动端默认初始态改为 `COLLAPSED`，避免首屏先展示大面积统计卡。

**结果**

- 折叠态不再像独立卡片，更接近页面内部的“上下文提示层”。
- 桌面端信息密度和移动端首屏效率都更稳。

## 4. 当前实现结论

### 4.1 统计卡的实现方式

当前多个页面的统计卡仍以 TSX 组件直接编排为主，并不是运行时从 JSON 配置文件渲染出来的。

例如：

- `frontend/src/pages/building/BuildingStats.tsx`
- `frontend/src/pages/student/StudentStats.tsx`
- `frontend/src/pages/occupancy/OccupancyStats.tsx`
- `frontend/src/pages/task-publish/TaskPublishStats.tsx`
- `frontend/src/pages/audit-log/AuditLogStats.tsx`

仓库里虽然存在：

- `doc/dorm_management_ui.json`
- `doc/task_publish_ui.json`

但目前更像设计/说明文档，没有发现前端页面在运行时直接读取这些 JSON 来生成统计卡。

### 4.2 组件层收益

- `PageLayout` 现在已经具备承载自定义统计区的能力，不再强制所有页面都用固定 `Row` 包裹。
- `CollapsibleStatsBoard` 和 `useContextualStatsState` 已经形成一套可复用基础设施，后续如果要把楼栋、学生、入住等页面也升级成折叠统计条，技术路径已经打通。
