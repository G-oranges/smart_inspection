## 2. 关键实现点

### Top 1（P0）：Excel 公式注入防护

**问题**：导出的 Excel 中若单元格值以 `=`, `+`, `-`, `@` 开头，会被 Excel 解析为公式执行，存在安全风险。

**修复方案**：

1. 新增 `frontend/src/utils/excelUtils.js`，实现 `sanitizeExcelCell(value)` 函数：
   - 检测字符串是否以危险字符开头
   - 如是，自动前置单引号 `'` 转义
2. 在所有导出路径调用 `sanitizeExcelRow()` 包装导出数据：
   - `handleDownloadFailedRows()`（Step6 失败行导出）
   - `handleDownloadErrorReport()`（Step6 异常分析报告）
   - `handleDownloadErrorRows()`（Step4 错误行导出）

### Top 2（P0）：preview/execute 请求统一走 apiRequestWithRefresh

**问题**：手写 `fetch` 未复用统一 client，401 无自动刷新、403 未处理，可能渲染误导性结果。

**修复方案**：

1. 删除 `getAuthHeaders()` 辅助函数
2. 将 preview 请求改为 `await apiRequestWithRefresh(config.api.preview, { method: 'POST', body: {...} })`
3. 将 execute 请求改为 `await apiRequestWithRefresh(config.api.execute, { method: 'POST', body: {...} })`
4. 错误处理改为 try-catch，apiRequestWithRefresh 会：
   - 401 自动刷新 token 后重试
   - 刷新失败或 403 抛出明确错误
   - 异常时显示 `err.message` 并保持页面在错误态
5. 移除调试用 `console.log`

### Top 3（P1）：大文件与行数上限保护

**问题**：无文件大小/行数上限，可能导致前端卡死或后端超时。

**修复方案**：

1. **前端文件大小校验**（`handleBeforeUpload`）：
   - 默认上限 5MB，来自 `config.limits.maxFileSize`
   - 超限则拒绝上传并提示
2. **前端行数校验**（`handleNext` Step3→Step4）：
   - 默认上限 5000 行，来自 `config.limits.maxRows`
   - 解析后超限则拒绝并提示
3. **后端行数校验**（Controller 层）：
   - PreviewImportDormsV2：超过 1000 行返回 413
   - ImportDormsV2：超过 1000 行返回 413
4. **附加修复**：execute 接口增加 strategy 白名单校验（SKIP/OVERWRITE）

## 4. 新增工具函数复用说明

### excelUtils.js

**位置**：`frontend/src/utils/excelUtils.js`

**导出函数**：

- `sanitizeExcelCell(value)` - 对单个值进行公式注入转义
- `sanitizeExcelRow(row)` - 对整行对象进行转义

**复用点**：

- 学生导入向导（错误行/失败行/报告导出）
- 入住导入向导（错误行/失败行/报告导出）
- 任何需要导出 Excel 且包含用户输入数据的场景

### importConfigs.js limits 配置

**新增字段**：

```javascript
limits: {
  maxFileSize: 5 * 1024 * 1024, // 文件大小上限
  maxRows: 5000,                // 行数上限
}
```

**复用点**：未来学生/入住导入配置可定义各自的 limits，无需修改组件代码。

## 6. 通用化与 P1 风险收敛记录 (2026-01-15)

**整改范围**：实现 ImportWizardModal 完全配置驱动，并解决行号错位、表头逻辑及后端 panic 等 P1 风险。

### A. 通用化重构 (Generalization)

1. **A1 - 移除业务硬编码**：
   - 移除了项目内所有"宿舍"相关的文案硬编码。
   - `config.notes`、`config.title`、`config.template.sampleRow` 驱动 Step 1 与 Step 5 的展示。
2. **A2 - 动态 codeFields**：
   - `preprocessRows` 现在从 `config.codeFields` 获取编码类字段名单，自动处理科学计数法转换。
3. **A3 - 强制列顺序一致性**：
   - 导出的错误行/失败行 Excel 列顺序现在完全由 `config.fields` 的物理定义顺序决定，确保与模板 100% 对齐。

### B. P1 风险收敛 (Robustness)

1. **B4 - 物理行号锁定**：
   - 修改 `XLSX.utils.sheet_to_json` 为 `blankrows: true`，并在手动过滤空行时保留原始索引。
   - **效果**：即使 Excel 中间有空行，导出的错误报告中的行号也能精准对应 Excel 的物理行号。
2. **B5 - 表头边界防御**：
   - **重复检测**：识别到重复表头名时强制阻断并提示，防止后端解析错位。
   - **归一化**：自动剔除表头中的 `\u200B`（零宽空格）等不可见字符。
3. **B6 - 后端执行兜底**：
   - 在 `BatchImportDormsV2` 中增加了必填字段的 `nil` 检查与业务校验。
   - **效果**：若前端绕过校验发送脏数据，后端不再返回 500 Panic，而是返回 200 并包含错误详情，实现业务闭环。

### C. 统计一致性修复

- **口径对齐**：通过 `Set(rowNo)` 去重统计，确保“可导入行数” + “需修复行数” = “总扫描行数”，解决了单行多错导致的统计虚高。
