# 登录策略与密码管理专项优化方案

## 1. 背景与目标

为了提升系统的安全性，需要对现有登录策略和密码管理机制进行专项优化。主要涉及初始密码统一化、临时密码生成、用户自主修改密码以及密码强度校验。

## 2. 可行性分析

- **后端**: 增加“修改密码”和“生成临时密码”接口开发难度低，不涉及已有核心业务逻辑的修改。临时密码可利用 Redis 的过期机制（TTL 12h）进行高效存储和自动清理。
- **前端**: 在账号管理页面增加单条操作入口，以及在顶栏增加个人设置入口，符合 Ant Design v6 的交互规范，风格保持统一。
- **数据结构**: 临时密码存储在 Redis 中，不改变 MySQL 数据库现有表结构。修改密码仅涉及 `user` 表 `password` 字段的更新。

## 3. 分步骤优化内容

### 第一阶段：密码策略调整（后端）

1.  **初始密码更新**:
    - 修改 `UserService.CreateUser` 和 `UserService.ResetPassword` 逻辑。
    - 初始密码统一设置为: `DEFAULT_INITIAL_PASSWORD` 环境变量配置的值。
    - 例外项：`root` 账号以及 4 个种子账号（admin, counselor, leader, student）保持原有逻辑或预置密码，不强制重置为该初始密码。
2.  **重置密码逻辑**:
    - 管理员在账号管理页点击“密码重置”时，将密码修改为 `DEFAULT_INITIAL_PASSWORD` 环境变量配置的值。

### 第二阶段：临时密码功能（后端 + 前端）

1.  **后端实现**:
    - 新增接口 `POST /api/users/:id/temporary-password`。
    - 生成规则：12 位字符，包含大小写字母、数字及标点符号。
    - 存储机制：Redis 存储，Key 为 `temp_pwd:{userId}`，Value 为加密后的临时密码，有效期 12 小时。
    - 登录逻辑：`AuthService.Login` 需同时校验数据库密码和 Redis 中的临时密码。
2.  **前端实现**:
    - `AccountPermissionPage.jsx` 表格操作列增加“生成临时密码”按钮。
    - 点击后弹窗显示生成的临时密码，并提供复制功能。

### 第三阶段：用户自主修改密码（后端 + 前端）

1.  **后端实现**:
    - 新增接口 `PUT /api/auth/change-password`。
    - 参数：`oldPassword`, `newPassword`。
    - 校验规则：新密码不少于 8 位，必须包含大小写字母、数字及标点符号。校验旧密码正确性。
2.  **前端实现**:
    - `Layout.jsx` 顶栏用户信息处增加“修改密码”菜单项。
    - 点击后弹出 `ChangePasswordModal`。
    - 前端表单增加强校验逻辑，确保符合复杂度要求。

### 第四阶段：登录界面调整

- 确保登录页暂不提供“忘记密码”功能（因缺乏手机/邮箱验证验证能力）。
- 检查并清理任何现有的忘记密码入口。

## 4. 进度安排

1.  编写优化方案（当前）。
2.  后端接口开发与测试。
3.  前端页面与交互开发。
4.  整体验收与文档更新。

## 5. 注意事项

- 保证审计日志记录完整（如：谁生成了临时密码，谁修改了密码）。
- 密码复杂度校验必须在前后端双重实现。
- 操作 root 账号需保持高度谨慎。
