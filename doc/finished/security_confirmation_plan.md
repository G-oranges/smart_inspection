# 重要操作二次确认安全增强方案

## 1. 目标

为了降低误操作风险，特别是针对涉及数据库增加（Create）、物理/逻辑删除（Delete）以及关键信息变更（Update）的操作，本项目拟在全站范围内实施二次确认机制。特别是针对数据导入功能，需从单一触发逻辑优化为"校验-摘要-决策-执行"的多步安全流程。

## 2. 设计规范

参照现有的"任务发布"界面，二次确认弹窗需满足以下要求：

- **视觉反馈**：使用 Ant Design 的 `Modal.confirm` 或 `Steps` 引导。对于删除等高风险操作，图标使用红色警示色（`ExclamationCircleOutlined`）。
- **信息展示**：弹窗正文需列出即将操作的关键数据摘要，让用户明确知道点击"确定"后会发生什么。
- **操作一致性**：确认按钮文字统一为"确认"，取消按钮统一为"取消"。

## 3. 功能模块梳理与确认方案

### 3.1 查寝任务管理 (`TaskPublishPage.jsx`)

- **操作 1**：发布新任务 / 保存编辑记录（**已有，需保持/优化**）。
- **操作 2**：删除任务（单个或批量）。
- **确认内容**：
  - 任务标题：`[任务名称]`
  - 风险提示：警告删除任务将导致该任务下的所有查寝成绩记录同步失效。
- **确认弹窗**：`确认删除选中的 [N] 个任务吗？此操作不可撤销。`

### 3.2 学生/教师管理 (`StudentManagementPage.jsx`, `TeacherManagementPage.jsx`)

- **操作 1**：单个/批量删除。
- **确认内容**：确认是否删除选中的 `[N]` 项记录，并展示首个记录的姓名作为概览。
- **操作 2**：新建/编辑人员。
- **确认内容**：展示姓名、学号/工号、所属部门/班级，确认保存。
- **操作 3**：Excel 数据导入（详见第 4 节）。

### 3.3 宿舍与基础建置 (`DormManagementPage.jsx`, `BuildingManagementPage.jsx`)

- **操作 1**：删除房间或楼栋。
- **确认内容**：
  - **关键警告**：如果房间内仍有学生入住，必须强制显示"该房间尚有 [N] 名学生，请先处理退宿"。
- **操作 2**：修改房间核定容量。
- **确认内容**：显示新旧容量对比，确认是否更新。

### 3.4 入住管理 (`OccupancyManagementPage.jsx`)

- **操作**：分配床位 / 办理退宿。
- **确认内容**：
  - 操作类型：`[分配/退宿]`
  - 目标学生：`[姓名]`
  - 目标位置：`[楼栋-房间-床位]`

### 3.5 账号与权限 (`AccountPermissionPage.jsx`)

- **操作 1**：修改用户角色。
- **操作 2**：重置密码。
- **确认内容**：确认重置 `[用户名]` 的密码为初始默认密码。
- **操作 3**：停用/激活账号。

### 3.6 系统设置 (`AdminSettingsPage.jsx`)

- **操作**：保存评分规则、扣分项配置。
- **确认内容**：提示配置修改将立即影响后续所有查寝评分逻辑。

## 4. 核心优化：数据导入安全增强流程

针对"学生导入"、"教师导入"、"宿舍导入"等功能，需将原有的"上传即执行"逻辑优化为以下四个阶段：

### 4.1 第一阶段：文件预检 (Pre-validation)

- **触发**：用户选择文件并点击"提交上传"。
- **后端执行**：后端解析文件但不写入数据库，返回预检结果。
- **返回数据结构**：
  - `total`: 总行数
  - `validCount`: 合规行数
  - `errors`: 格式错误列表 (包含行号、字段名及错误原因)
  - `conflicts`: 数据冲突列表 (学号/工号已存在、资源被占用等业务逻辑冲突)

#### 4.1.1 导入校验细化方案 (详细规则)

为了确保数据的准确性与安全性，前后端需协同执行以下校验。若预检失败，需明确告知用户失败的类型及具体行号。

| 校验分类         | 错误类型          | 检查层级        | 详细描述与处理方案                                                           | 错误提示示例                                                   |
| :--------------- | :---------------- | :-------------- | :--------------------------------------------------------------------------- | :------------------------------------------------------------- |
| **文件合规性**   | 文件类型有误      | 前端 + 后端     | 仅允许 `.xlsx` 或 `.xls`。若前端检测不通过，直接拦截。                       | "文件格式不支持，请下载正确的 Excel 模板后再试。"              |
|                  | 文件损坏/网络异常 | 后端 (解析层)   | 后端在解析 Excel 时若捕获 `EOF` 或数据流不完整错误，视为网络中断或文件损坏。 | "文件解析失败，可能是网络传输中断或文件已损坏，请重新上传。"   |
| **模板正确性**   | 文件内容为空      | 后端            | 检测到有效数据行为 0 行。                                                    | "导入失败：文件内未检测到有效的学生/教师记录。"                |
|                  | 表头不匹配        | 后端            | 检查第一行表头字段是否与系统要求的模板字段一致且齐全。                       | "表头校验不通过：缺少 [学号] 字段或表头顺序有误，请对比模板。" |
| **字段合规性**   | 类型不匹配        | 后端            | 例如："床号"应为数字却填入了文字。                                           | "第 [N] 行 [床号] 字段类型有误：预期为数字，实际为 [内容]。"   |
|                  | 超过长度限制      | 后端            | 检查字段长度是否超过数据库定义（如姓名限定 50 字符）。                       | "第 [N] 行 [姓名] 长度超限：最大允许 50 字符。"                |
|                  | 非法字符          | 后端            | 检查内容是否包含控制字符或可能导致后端解析/计算出错的特殊符号。              | "第 [N] 行 [姓名] 包含非法不可见字符，请清理后再导入。"        |
| **业务逻辑冲突** | 唯一标识重复      | 后端 (数据库)   | 学号或工号已存在于数据库中。                                                 | "第 [N] 行冲突：学号 [12345] 已被学生 [张三] 使用。"           |
|                  | 资源独占冲突      | 后端 (逻辑检查) | 例如：导入学生分配宿舍时，目标床位已被他人居住。                             | "第 [N] 行冲突：宿舍 [302-1 号床] 已被占用，无法重复分配。"    |
|                  | 引用记录不存在    | 后端 (外键)     | 导入学生时，填写的"楼栋名称"在系统中无法找到。                               | "第 [N] 行错误：系统内找不到名为 [1 号楼] 的楼栋。"            |

#### 4.1.2 宿舍管理页面专属校验规则

宿舍管理是在 **楼栋管理** 的基础上进行房间的细化管理。因此，宿舍导入/新增时必须遵循以下约束：

**核心原则**：宿舍的楼栋和楼层信息必须来源于 `楼栋管理` 中的已有数据，不允许凭空创建。

| 操作方式       | 楼栋字段   | 楼层字段               | 校验逻辑                                                         |
| :------------- | :--------- | :--------------------- | :--------------------------------------------------------------- |
| **页面新增**   | 下拉框选择 | 根据楼栋动态加载下拉框 | 前端已限制，只能从已有数据中选择                                 |
| **Excel 导入** | 文本输入   | 文本输入               | 后端预检时校验楼栋名称是否存在、楼层是否在该楼栋的有效楼层范围内 |

**具体校验规则**：

| 校验项           | 规则描述                                                         | 错误提示示例                                                           |
| :--------------- | :--------------------------------------------------------------- | :--------------------------------------------------------------------- |
| 楼栋存在性       | 导入的"楼栋"字段值必须在 `Building` 表中存在（按 `name` 列匹配） | "第 [N] 行错误：楼栋 [5 号楼] 不存在，请先在楼栋管理中添加。"          |
| 楼层有效性       | 导入的"楼层"必须在目标楼栋的 `floors` 配置范围内（如 1~6 层）    | "第 [N] 行错误：楼层 [7] 超出 [3 号楼] 的有效楼层范围 (1-6)。"         |
| 房间号重复       | 同一楼栋内房间号不能重复（`building + roomNo` 唯一约束）         | "第 [N] 行冲突：3 号楼 301 已存在，选择覆盖或跳过。"                   |
| 房间号格式一致性 | 房间号的首位数字通常应与所在楼层一致（如 301 应在 3 层）         | "第 [N] 行警告：房间号 [501] 首位数字 (5) 与楼层 (3) 不一致，请确认。" |

**前端新增页面要求**：

- **楼栋选择**：使用下拉框，数据源为 `GET /api/infra/buildings` 返回的楼栋列表
- **楼层选择**：根据选中的楼栋动态加载，数据源为 `GET /api/infra/floors?building=楼栋名`

校验类型 字段 规则
必填校验 楼栋、房间号 不能为空
长度校验 楼栋 ≤ 50 字符
长度校验 房间号 ≤ 20 字符
长度校验 校区 ≤ 50 字符
长度校验 宿舍性别 ≤ 10 字符
长度校验 年级 ≤ 20 字符
数值校验 可住人数 ≥ 0
数值校验 楼层 ≥ 0
冲突检测 楼栋+房间号 数据库唯一约束

### 4.2 第二阶段：校验摘要展示 (Modal Summary)

弹窗展示以下信息：

- **统计摘要**：
  - ✅ 准备就绪：`X` 条
  - ⚠️ 存在冲突：`Y` 条 (提示：这些记录在系统中已存在)
  - ❌ 格式错误：`Z` 条 (提示：这些记录将无法导入)
- **错误详情**：在 Modal 内使用折叠面板或列表显示"错误记录"的原因及行号。

### 4.3 第三阶段：冲突决策 (Conflict Resolution)

针对 `Y` 条冲突数据，提供单选配置：

- **覆盖导入**：更新已存在的记录。
- **跳过冲突**：仅导入新记录，保留原有记录。
- **取消导入**：终止本次操作。

### 4.4 第四阶段：最终执行 (Final Execution)

- 用户在 Modal 中点击"确认导入"后，前端发送携带 `resolution` 参数的请求，后端执行最终写入并返回最终结果。

## 6. 错误提示弹窗规范

针对异步操作（如文件导入、API 请求）的失败场景，**必须使用 `Modal.error` 弹窗**展示详细错误信息，而非简单的 `message.error` 或 `setMessage`。

### 6.1 预检失败 (Pre-validation Error)

当文件预检阶段发生错误时，弹窗需根据错误类型展示针对性建议：

- **标题**：`文件预检失败`
- **内容展示逻辑**：
  - **模板/格式类**：提供下载模板按钮的提示。
  - **内容细节类**：罗列具体的行号、字段名及错误原因（支持滚动查看）。
  - **网络/系统类**：提示稍后重试或检查文件完整性。

**示例 UI 结构**：

```javascript
Modal.error({
  title: "导入预检未通过",
  width: 600,
  content: (
    <div>
      <p>我们在解析您的文件时发现了以下问题，请修正后重新上传：</p>
      <div
        style={{
          maxHeight: "300px",
          overflowY: "auto",
          background: "#fff7f7",
          padding: "12px",
          border: "1px solid #ffccc7",
          borderRadius: "4px",
        }}
      >
        <ul style={{ paddingLeft: 20, margin: 0 }}>
          {/* 示例：结构性错误 */}
          <li style={{ color: "#cf1322", fontWeight: "bold" }}>
            [全局错误] 文件表头与模板不匹配，请下载最新模板。
          </li>

          {/* 示例：行级错误 */}
          <li>第 5 行 [姓名]：长度超过 50 个字符。</li>
          <li>第 8 行 [学号]：系统中已存在相同学号 (2023001)。</li>
          <li>第 12 行 [宿舍]：目标床位 (302-A) 已被其他学生占用。</li>
        </ul>
      </div>
      <p style={{ marginTop: 12 }}>
        💡 <b>建议：</b>您可以点击页面上的 "下载模板" 按钮获取正确格式的 Excel
        文件。
      </p>
    </div>
  ),
});
```

### 6.2 导入执行失败 (Import Execution Error)

当最终导入执行阶段发生错误时，弹窗需包含：

- **标题**：`导入执行失败`
- **内容**：简要说明 + 红色高亮显示后端返回的具体错误信息

**示例代码**：

```javascript
Modal.error({
  title: "导入执行失败",
  content: (
    <div>
      <p>数据导入过程中发生错误：</p>
      <p style={{ marginTop: 8, color: "#ff4d4f" }}>
        {err.message || "未知错误"}
      </p>
    </div>
  ),
});
```

### 6.3 通用规范

| 场景                           | 使用方式                              | 备注              |
| ------------------------------ | ------------------------------------- | ----------------- |
| 轻量提示（成功、警告）         | `message.success` / `message.warning` | 3 秒后自动消失    |
| 严重错误（需用户了解详细原因） | `Modal.error`                         | 用户需手动关闭    |
| 确认类操作                     | `Modal.confirm`                       | 提供确认/取消按钮 |
