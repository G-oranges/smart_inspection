# 宿舍管理页级联筛选与列表字段增强方案 (Design Specification)

## 1. 设计概述

基于现有 UI 资产，对资源管理核心路径进行增强。不改动核心组件代码，通过配置与逻辑复用实现 Apple 级交互体验。

## 2. 交互逻辑定义

### A. 学院-专业-班级级联筛选

- **触发入口**：`FilterDropdownPanel` (Desktop) / `MobileAdvancedFilter` (Mobile)。
- **操作逻辑**：
  1. **级联性**：改变上级（如学院），强制重置下级（专业、班级）的选择态。
  2. **点即刷新**：利用 `useState` 闭包与 `useEffect` 侦查，任何一级点击即触发表格 `reload`。
  3. **路径存储**：在筛选区域显示当前完整的路径 Chips (e.g., `[资源学院] > [植保专业]`)。

### B. 列表字段优化

- **字段 1：所属学院 (`colleges`)**
  - **来源**：实时聚合 `studentList` 字段。
  - **空态处理**：若宿舍内无学生或学生无学院信息，显示 `-`。
  - **展示**：多学院时使用 `AntD Tag` 配合 `Space` 换行，移动端使用逗号分隔或 `+N`。
- **字段 2：年级 (`grades`)**
  - **逻辑变更**：由固定单一值变为“学生年级集合”。
  - **筛选规则**：`OR` 匹配。只要舍内有一人符合筛选年级，该宿舍显现。

## 3. 视觉规范 (Apple HIG)

- **色彩**：选中态必须使用 `System Blue (#007AFF)`。
- **形状**：Tag 全部使用 `rounded-full` (Capsule 风格)。
- **模糊反馈**：移动端级联层级切换时，背景应保持 `backdrop-blur-xl` 特性。

## 4. 边界处理

- **数据残留**：当清除“学院”筛选时，下方表格应立即恢复全量显现。
- **空宿舍过滤**：空宿舍在任何“学生维度”筛选（学院/年级/班级）下均不应出现。
