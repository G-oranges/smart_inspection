# 邮箱域名白名单持久化与输入优化 - 进展文档

## 1. 任务背景

- **需求**:
  1. 个人中心邮箱输入改为“前缀输入 + 固定 @ + 域名下拉”，域名来自系统设置白名单。
  2. 实现系统设置中“可用邮箱域名”的增删功能。
  3. 修复域名配置在退出登录后（后端重启或数据库未同步）消失的问题。

## 2. 实施方案与完成情况

### 2.1 前端输入 UI 优化 (已完成)

- [x] **AppLayout.jsx 改造**:
  - 将邮箱输入框拆分为 `Input` (前缀) + `Select` (域名选择)。
  - 域名下拉框选项绑定至 `settings.contactEmailDomains`。
  - 增加未配置域名时的禁用处理与红色提示语。
  - 适配移动端 (底部 Drawer) 与桌面端。

### 2.2 后端数据持久化修复 (已完成)

- [x] **Go 模型更新**: 在 `internal/model/models.go` 的 `SystemSettings` 结构体中新增 `ContactEmailDomains` 字段（`datatypes.JSON` 类型），确保存入数据库时对应的 `contactEmailDomains` 列能被映射。
- [x] **数据库自动迁移**: 在 `cmd/server/main.go` 的数据库初始化流程（`initDB`）中添加 `AutoMigrate(&model.SystemSettings{})`，确保后端启动时自动在 MySQL 数据库中创建缺少的列。

### 2.3 验证与测试建议

- [ ] **系统设置测试**:
  1. 进入“系统设置 -> 系统概览”。
  2. 在“可用邮箱域名”一栏添加几个域名（如 `gmail.com`, `foxmail.com`）。
  3. 点击顶部“保存更改”。
- [ ] **持久化测试**:
  1. 刷新页面或退出登录重新进入，确认刚添加的域名是否依然存在。
  2. 重启 Go 后端进程（可选，已通过 `AutoMigrate` 保障）。
- [ ] **个人中心交互测试**:
  1. 进入“个人信息 -> 联系方式”。
  2. 确认邮箱输入部分是否显示为“前缀 + @ + 下拉框”。
  3. 确认下拉框中内容与系统设置一致。

## 3. 待办事项

- [ ] 确保前端所有引用邮箱的地方都已适配新的分段存储逻辑。
