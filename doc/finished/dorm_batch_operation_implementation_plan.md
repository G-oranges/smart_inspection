# 宿舍入住管理批量操作实施方案 (Implementation Plan)

## 1. 目标概述

在宿舍管理页面引入高效的批量操作工具栏，支持多选退宿、批量入住、批量交换学生。同步将界面重构为支持字段自定义配置的列表形式，并全面支持 Excel 导入进行入住分配与迁移。

## 2. 权限与日志设计

### 2.1 方案 B：专用权限码 `DORM_CHECKIN_MANAGE`

系统将引入独立的权限项，实现“宿舍基础架构维护”与“入住业务操作”的权责分离：

- **权限标识**：`DORM_CHECKIN_MANAGE`
- **显示名称**：宿舍入住管理
- **管理逻辑**：
  - **前端逻辑**：
    - 只有拥有此权限的用户，才能在“宿舍管理”页面看到并触发批量入住、批量退宿、批量交换按钮。
    - 只有拥有此权限的用户，才能看到“Excel 人员操作”入口。
    - `canCheckIn = hasPermission("DORM_CHECKIN_MANAGE")`。
  - **后端逻辑**：
    - 所有入住相关接口（Checkout, Checkin, Exchange, ExcelImport）均需通过权限中间件校验此权限码。
    - 确保即便是拥有 `DORM_EDIT`（宿舍属性编辑权）的用户，若未被授予 `DORM_CHECKIN_MANAGE`，也无法变动学生入住状态。

### 2.2 变动日志 (ResidencyLog) - 细化

入住状态的每一次变动都必须实现“可回溯”：

- **事务性**：所有批量操作必须在数据库事务内完成，确保数据的原子性。
- **记录维度**：
  - `OperatorID`：谁操作的。
  - `ChangeType`：入住/退宿/交换/迁移/Excel 导入。
  - `SourceDetail`：变动前状态（原宿舍、原床位）。
  - `TargetDetail`：变动后状态（新宿舍、新床位）。
  - `Remark`：如果是 Excel 导入，需注明来源文件名。

## 3. 界面重构 (UI/UX) - 细化

### 3.1 列表视图增强

- **感官升级**：将现有的大表格改为“紧凑型列表”，利用 HSL 色彩系统高亮显示“满员”、“未满”、“已封寝”等状态。
- **动态列配置**：
  - 引入 `useTableColumns` 钩子，支持字段持久化。
  - **关键字段（默认隐藏或可选）**：性别要求、适用年级、宿管员信息、最近检查结果、当前学生名单（点击展开）。
- **字段管理**：复用学生管理页面的 `TableFieldSettings` 组件。

### 3.2 批量操作工具栏

- **触发机制**：当选中的宿舍数量 > 0 时，吸底显示浮动操作栏。
- **前端实时校验**：
  - **退宿**：校验选中宿舍是否有人入住。
  - **入住**：校验选中宿舍是否有空余床位。
  - **交换**：校验是否恰好选中 2 个宿舍，且性别/年级等属性是否兼容。

## 4. 批量操作校验流程（核心保护逻辑）

### 4.1 自动校验引擎

在用户点击批量操作按钮前，前端必须通过 `OperationValidator` 引擎执行合规性检查：

1. **类型兼容性**：选中的宿舍性别设置必须一致。
2. **容量预警**：如果是批量入住，实时计算 `SelectedTotalCapacity - SelectedCurrentOccupancy`，若学生数超过余额，严禁提交并显示差值。
3. **状态校验**：对于“维修中”或“停用”状态的宿舍，自动禁用入住操作。

## 5. 批量操作逻辑

### 5.1 多选退宿 (Batch Checkout)

- **后端**：`POST /api/infra/dorms/batch-checkout`
- **处理**：清空指定宿舍所有学生的关联信息，并在 `student` 表执行批量更新，同步记录日志。

### 5.2 批量入住 (Batch Check-in)

- **交互**：弹出分步对话框。
  1. 预览选中宿舍空位。
  2. 选择学生（支持搜索）。
  3. 确认分配。
- **校验**：检查操作后是否超过宿舍 Capacity，检查性别冲突。

### 5.3 批量交换 (Batch Exchange)

- **要求**：恰好选中两个宿舍。
- **功能**：
  - **全员交换**：A 宿舍与 B 宿舍全员互换。
  - **部分交换**：弹出交互界面，手动勾选 A 与 B 宿舍中需要对调的学生名单。

## 6. Excel 深度支持 - 流程分解

### 6.1 批量入住/迁移工作流

1. **上传阶段**：后端解析 Excel，提取 `StudentNo` 和映射的 `DormInfo`。
2. **静默校验阶段**：
   - 学号是否存在？
   - 学生性别是否匹配？
   - 目标宿舍是否存在且有位？
3. **冲突报告**：若存在问题，返回与“学生管理”页面一致的结构化错误报告（行号、原因、原内容）。
4. **事务执行**：校验 100% 通过后（或用户选择忽略非致命错误），一键执行，同步更新 `student` 表和 `ResidencyLog`。

### 6.2 批量交换 Excel

- **场景**：跨楼栋、跨宿舍的大规模人员调整。
- **表格列**：`学号`、`原宿舍`、`新宿舍`。后端采用事务处理，确保交换过程不产生“孤儿”入住记录。

### 6.3 批量迁移 (Batch Migration)

- **场景**：整个宿舍或班级换寝。支持将一批学生从旧宿舍群一键迁移到选中的新宿舍群，并在 Excel 中保留对应关系。

## 7. 实施步骤

1.  **Phase 1**: UI 列表化重构与动态列配置方案落地。
2.  **Phase 2**: 批量退宿功能集成（含后端接口与 ResidencyLog 支持）。
3.  **Phase 3**: 批量入住/交换功能开发（含前端复杂验证逻辑）。
4.  **Phase 4**: Excel 批量操作支持（预检、冲突报告、最终导入）。
5.  **Phase 5**: 整体性能优化与移动端适配验证。
