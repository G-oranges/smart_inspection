## 一、执行摘要（Executive Summary）

### 1.1 现状结论（5 条核心发现）

1. **巨石页面无模块边界**：5 个管理页面（Student/Dorm/Teacher/Occupancy/Account）代码量 1402-2751 行，每个页面同时承担数据获取、状态管理、UI 渲染、业务逻辑四重职责
2. **筛选/表格逻辑 100% Copy-Paste**：`normalizeFilterValues`、`areArraysEqual`、`areFiltersEqual`、`buildTableParams`、`handleSearch`、`handleResetFilters` 六个函数在 4 个页面中代码体完全相同或仅字段名不同
3. **表格数据加载模式未封装**：每个页面都手写 `useEffect` + `AbortController` + `setLoading` + `catch` + `finally` 模式，存在竞态风险点
4. **hooks 层封装模式同构但重复**：`useStudents`/`useDorms`/`useTeachers`/`useUsers` 四个 hook 结构完全相同，均为 `useState` + `useCallback` + `tokenManager` 检查
5. **通用组件存在但未充分复用**：`ImportWizardModal`/`FilterDropdownPanel` 已组件化，但各页面仍有 `handleImport`/`handleConfirmImport` 本地重复代码

### 1.2 P0/P1/P2 核心目标与预期收益

| 阶段   | 目标                         | 核心产出                                                   | 预期改进                    |
| ------ | ---------------------------- | ---------------------------------------------------------- | --------------------------- |
| **P0** | 消除 6 个最高频重复函数/模式 | `filterUtils.js` + `useTableFetch.js` + `useTableState.js` | 每页减少 200-400 行重复代码 |
| **P1** | 建立配置驱动的管理页模式     | `useManagementPage.js` + `MobileEntityCard.jsx`            | 页面代码量降至 600-800 行   |
| **P2** | 工程守护（防止复发）         | ESLint 规则 + 目录约束 + 单测覆盖                          | 新增重复代码可被 CI 拦截    |

### 1.3 最大风险点与收口策略

| 风险点             | 描述                                                                                             | 收口策略                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **竞态条件**       | 当前 `useEffect` 内的 `AbortController` 逻辑分散，部分页面未正确处理 `controller.signal.aborted` | `useTableFetch` 内置竞态保护，提供 `isFresh` 回调判定                   |
| **模板化过早**     | `ManagementPageTemplate` 若 props 膨胀，将变成 God Component                                     | P1 阶段先只做 hooks 层统一，UI 模板作为 P2 可选项                       |
| **筛选配置差异**   | 各页面 `FILTER_KEYS` 不同（Student 8 个，Teacher 1 个）                                          | 提取配置到 `constants/filterConfigs/`，`filterUtils` 接收配置而非硬编码 |
| **性别归一化特例** | `normalizeStudentGender` vs `normalizeDormGender` 逻辑略有不同                                   | 保留 `normalizers` 配置注入点，不强制统一                               |

### 5.1 filterUtils.js

```javascript
// src/utils/filterUtils.js

/**
 * 将筛选值数组归一化为可比较的字符串数组
 * @param {unknown[]} values
 * @returns {string[]}
 */
export function normalizeFilterValues(values) {
  if (!Array.isArray(values)) return [];
  return values.map((v) => String(v)).sort();
}

/**
 * 两个字符串数组是否完全相等
 * @param {string[]} a
 * @param {string[]} b
 * @returns {boolean}
 */
export function areArraysEqual(a, b) {
  if (a.length !== b.length) return false;
  for (let i = 0; i < a.length; i++) {
    if (a[i] !== b[i]) return false;
  }
  return true;
}

/**
 * 两个筛选对象是否相等
 * @param {Record<string, string[]>} left
 * @param {Record<string, string[]>} right
 * @param {string[]} filterKeys - 需要比较的 key 列表
 * @returns {boolean}
 */
export function areFiltersEqual(left, right, filterKeys) {
  return filterKeys.every((key) =>
    areArraysEqual(
      normalizeFilterValues(left?.[key]),
      normalizeFilterValues(right?.[key]),
    ),
  );
}

/**
 * 创建默认空筛选对象
 * @param {string[]} filterKeys
 * @returns {Record<string, string[]>}
 */
export function createDefaultFilters(filterKeys) {
  const result = {};
  filterKeys.forEach((key) => {
    result[key] = [];
  });
  return result;
}

/**
 * 从 URL 参数创建初始筛选对象
 * @param {URLSearchParams} searchParams
 * @param {string[]} filterKeys
 * @returns {Record<string, string[]>}
 */
export function createInitialFilters(searchParams, filterKeys) {
  const result = {};
  filterKeys.forEach((key) => {
    result[key] = searchParams.getAll(key) || [];
  });
  return result;
}
```

### 5.2 tableParamsBuilder.js

> [!IMPORTANT]
> **补强点E：类型安全**
> `normalizers` 的输入可能来自 Select 的 value（number/object），不一定是 string。
> 实现时先 `String(v)` 统一转字符串，再交给 normalizer 处理，避免类型不一致问题。

```javascript
// src/utils/tableParamsBuilder.js

/**
 * 创建表格参数构建函数
 * @param {Object} config
 * @param {string[]} config.filterKeys - 筛选字段列表
 * @param {Record<string, (v: unknown) => string>} [config.normalizers] - 字段值归一化器，输入为 unknown
 * @returns {Function}
 */
export function createBuildTableParams(config) {
  const { filterKeys, normalizers = {} } = config;

  /**
   * @param {Record<string, unknown[]>} appliedFilters
   * @param {string} appliedSearchTerm
   * @param {{current: number, pageSize: number}} pagination
   * @param {string} sortField
   * @param {'asc'|'desc'} sortOrder
   * @param {boolean} [withPaging=true]
   * @returns {Record<string, unknown>}
   */
  return function buildTableParams(
    appliedFilters,
    appliedSearchTerm,
    pagination,
    sortField,
    sortOrder,
    withPaging = true,
  ) {
    const params = {};

    // 处理筛选参数
    filterKeys.forEach((key) => {
      const values = appliedFilters[key];
      if (values?.length) {
        // 🔧 补强点E：先统一转 string，再应用 normalizer
        const stringValues = values.map((v) => String(v));
        params[key] = normalizers[key]
          ? stringValues.map(normalizers[key])
          : stringValues;
      }
    });

    // 搜索词
    if (appliedSearchTerm?.trim()) {
      params.search = appliedSearchTerm.trim();
    }

    // 排序（总是带）
    params.sortField = sortField;
    params.sortOrder = sortOrder;

    // 分页（可选）
    if (withPaging) {
      params.page = pagination.current;
      params.pageSize = pagination.pageSize;
    }

    return params;
  };
}
```

### 5.3 useTableFetch.js

> [!IMPORTANT]
> **关键设计决策**
>
> 1. **isFresh 参数**：`onSuccess(data, isFresh)` 中的 `isFresh` 表示"此结果是否来自最新一次请求"。实现上通过 `fetchId === fetchIdRef.current && !signal.aborted` 判定后再传入 `true`，否则回调不会被调用（相当于隐式 `isFresh=false` 不触发）。如果未来需要"旧请求也触发 onSuccess 但标记 isFresh=false"，需调整逻辑。
> 2. **refetch 竞态**：`refetch()` 必须 abort 上一次请求（无论来自 effect 还是前一次 refetch），避免快速连续点击造成并发。通过维护 `activeControllerRef` 实现。
> 3. **网络浪费 vs 状态安全**：即使旧请求被 fetchIdRef 屏蔽写状态，仍会消耗网络资源。abort 机制既防状态污染，也减少无效请求。

```javascript
// src/hooks/useTableFetch.js
import { useState, useEffect, useRef, useCallback } from "react";

/**
 * @template T
 * @param {Object} options
 * @param {(params: any, opts?: {signal?: AbortSignal}) => Promise<{items: T[], total: number}>} options.fetchFn
 * @param {() => Record<string, unknown>} options.buildParams
 * @param {boolean} [options.enabled=true]
 * @param {(data: {items: T[], total: number}, isFresh: boolean) => void} [options.onSuccess]
 * @param {(error: Error) => void} [options.onError]
 * @param {unknown[]} [options.deps=[]]
 * @param {boolean} [options.keepPreviousData=false]
 * @returns {{data: {items: T[], total: number}, loading: boolean, error: string|null, refetch: () => void, isFetching: boolean}}
 */
export function useTableFetch(options) {
  const {
    fetchFn,
    buildParams,
    enabled = true,
    onSuccess,
    onError,
    deps = [],
    keepPreviousData = false,
  } = options;

  const [data, setData] = useState({ items: [], total: 0 });
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);
  const [isFetching, setIsFetching] = useState(false);
  const fetchIdRef = useRef(0);
  // 🔧 补强点B：维护活跃 controller，确保任何新请求前先 abort 上一次
  const activeControllerRef = useRef(null);

  const doFetch = useCallback(
    async (signal) => {
      const fetchId = ++fetchIdRef.current;

      if (!keepPreviousData) {
        setLoading(true);
      }
      setIsFetching(true);
      setError(null);

      try {
        const params = buildParams();
        const result = await fetchFn(params, { signal });

        // 🔧 补强点A：正确计算 isFresh 并传递
        const isFresh = fetchId === fetchIdRef.current && !signal?.aborted;
        if (isFresh) {
          setData(result);
          onSuccess?.(result, isFresh);
        }
      } catch (err) {
        if (signal?.aborted) return;
        if (fetchId === fetchIdRef.current) {
          const errorMsg = err.message || "请求失败";
          setError(errorMsg);
          setData({ items: [], total: 0 });
          onError?.(err);
        }
      } finally {
        if (fetchId === fetchIdRef.current && !signal?.aborted) {
          setLoading(false);
          setIsFetching(false);
        }
      }
    },
    [fetchFn, buildParams, onSuccess, onError, keepPreviousData],
  );

  useEffect(() => {
    if (!enabled) return;

    // 🔧 补强点B：先 abort 上一次请求
    activeControllerRef.current?.abort();
    const controller = new AbortController();
    activeControllerRef.current = controller;

    doFetch(controller.signal);

    return () => controller.abort();
  }, [enabled, ...deps]);

  // 🔧 补强点B：refetch 也要 abort 上一次
  const refetch = useCallback(() => {
    activeControllerRef.current?.abort();
    const controller = new AbortController();
    activeControllerRef.current = controller;
    doFetch(controller.signal);
  }, [doFetch]);

  return { data, loading, error, refetch, isFetching };
}
```

### 5.4 useTableState.js

```javascript
// src/hooks/useTableState.js
import { useState, useMemo, useCallback, useEffect } from "react";
import { useSearchParams } from "react-router-dom";
import {
  createDefaultFilters,
  createInitialFilters,
  areFiltersEqual,
} from "../utils/filterUtils";

/**
 * @param {Object} config
 * @param {string[]} config.filterKeys
 * @param {string} config.defaultSortField
 * @param {'asc'|'desc'} [config.defaultSortOrder='asc']
 * @param {number} [config.defaultPageSize=10]
 * @param {boolean} [config.syncUrl=true]
 */
export function useTableState(config) {
  const {
    filterKeys,
    defaultSortField,
    defaultSortOrder = "asc",
    defaultPageSize = 10,
    syncUrl = true,
  } = config;

  const [searchParams, setSearchParams] = useSearchParams();

  // 初始化状态
  const [draftFilters, setDraftFilters] = useState(() =>
    createInitialFilters(searchParams, filterKeys),
  );
  const [appliedFilters, setAppliedFilters] = useState(() =>
    createInitialFilters(searchParams, filterKeys),
  );
  const [draftSearchTerm, setDraftSearchTerm] = useState(
    () => searchParams.get("search") || "",
  );
  const [appliedSearchTerm, setAppliedSearchTerm] = useState(
    () => searchParams.get("search") || "",
  );
  const [sortField, setSortField] = useState(
    () => searchParams.get("sortField") || defaultSortField,
  );
  const [sortOrder, setSortOrder] = useState(
    () => searchParams.get("sortOrder") || defaultSortOrder,
  );
  const [pagination, setPagination] = useState({
    current: Number(searchParams.get("page")) || 1,
    pageSize: Number(searchParams.get("pageSize")) || defaultPageSize,
    total: 0,
  });
  const [selectedIds, setSelectedIds] = useState([]);
  const [selectAcrossPages, setSelectAcrossPages] = useState(false);

  // isDirty 计算
  const isDirty = useMemo(() => {
    const filtersEqual = areFiltersEqual(
      draftFilters,
      appliedFilters,
      filterKeys,
    );
    const searchEqual = draftSearchTerm.trim() === appliedSearchTerm.trim();
    return !(filtersEqual && searchEqual);
  }, [
    draftFilters,
    appliedFilters,
    draftSearchTerm,
    appliedSearchTerm,
    filterKeys,
  ]);

  // 应用筛选
  const applyFilters = useCallback(() => {
    if (!isDirty) return;
    setAppliedFilters(draftFilters);
    setAppliedSearchTerm(draftSearchTerm);
    setPagination((prev) => ({ ...prev, current: 1 }));
    setSelectedIds([]);
    setSelectAcrossPages(false);
  }, [isDirty, draftFilters, draftSearchTerm]);

  // 重置
  const resetAll = useCallback(() => {
    const defaultFilters = createDefaultFilters(filterKeys);
    setDraftFilters(defaultFilters);
    setAppliedFilters(defaultFilters);
    setDraftSearchTerm("");
    setAppliedSearchTerm("");
    setSortField(defaultSortField);
    setSortOrder(defaultSortOrder);
    setPagination((prev) => ({ ...prev, current: 1 }));
    setSelectedIds([]);
    setSelectAcrossPages(false);
  }, [filterKeys, defaultSortField, defaultSortOrder]);

  // 表格变化处理
  const handleTableChange = useCallback((newPagination, _filters, sorter) => {
    setPagination((prev) => ({
      ...prev,
      current: newPagination.current,
      pageSize: newPagination.pageSize,
    }));
    if (sorter.field && sorter.order) {
      setSortField(sorter.field);
      setSortOrder(sorter.order === "ascend" ? "asc" : "desc");
    }
  }, []);

  // 🔧 补强点C：URL 同步 (可选)
  // 设计决策：使用 replace: true 避免每次筛选变化都产生历史记录，用户无需 back 回到上一个筛选状态
  // 如需 push 模式（可回退），可配置 urlHistoryMode: 'push' | 'replace'
  useEffect(() => {
    if (!syncUrl) return;
    const params = new URLSearchParams();
    // 🔧 补强点C：显式 String() 转换，避免隐式转换问题
    if (pagination.current !== 1)
      params.set("page", String(pagination.current));
    if (pagination.pageSize !== defaultPageSize)
      params.set("pageSize", String(pagination.pageSize));
    if (sortField !== defaultSortField) params.set("sortField", sortField);
    if (sortOrder !== defaultSortOrder) params.set("sortOrder", sortOrder);
    if (appliedSearchTerm.trim())
      params.set("search", appliedSearchTerm.trim());
    filterKeys.forEach((key) => {
      (appliedFilters[key] || []).forEach((v) => params.append(key, String(v)));
    });
    setSearchParams(params, { replace: true });
  }, [
    pagination.current,
    pagination.pageSize,
    sortField,
    sortOrder,
    appliedSearchTerm,
    appliedFilters,
    syncUrl,
    setSearchParams,
    filterKeys,
    defaultSortField,
    defaultSortOrder,
    defaultPageSize,
  ]);

  // 🔧 补强点D：筛选变化时清空选择
  // 规则：applyFilters/resetAll 触发时清空选择；pagination/sort 变化时 **不** 清空当页选择
  // 跨页选择语义：当 selectAcrossPages=true 时，selectedIds 为空数组，表示"选中全部符合筛选条件的结果"
  // 如需"排除列表"语义（selectedIds 存储被取消选择的 ID），需额外实现 excludedIds 状态
  useEffect(() => {
    setSelectedIds([]);
    setSelectAcrossPages(false);
  }, [appliedFilters, appliedSearchTerm]);

  return {
    // 筛选
    draftFilters,
    appliedFilters,
    setDraftFilter: (key, value) =>
      setDraftFilters((prev) => ({ ...prev, [key]: value })),
    setDraftFilters,
    // 搜索
    draftSearchTerm,
    appliedSearchTerm,
    setDraftSearchTerm,
    // 分页排序
    pagination,
    setPagination,
    sortField,
    sortOrder,
    setSortField,
    setSortOrder,
    // 选择
    selectedIds,
    setSelectedIds,
    selectAcrossPages,
    setSelectAcrossPages,
    // 工具
    isDirty,
    applyFilters,
    resetAll,
    handleTableChange,
  };
}
```

// src/utils/tableHelpers.js
import React from "react";
import { Space, Button, Popconfirm } from "antd";
import { EyeOutlined, EditOutlined, DeleteOutlined } from "@ant-design/icons";

/**
 * 创建表格操作列
 * @param {Object} config
 * @param {(record: any) => void} [config.onView]
 * @param {(record: any) => void} [config.onEdit]
 * @param {(record: any) => void} [config.onDelete]

export function createActionColumn(config) {
  const {
    onView,
    onEdit,
    onDelete,
    canEdit = true,
    canDelete = true,
    deleteLoading = false,
    deleteConfirmTitle = "确定删除吗？",

  } = config;

  return {
    title: "操作",
    key: "action",
    width: onView ? 200 : 140,
    fixed: "right",

            size="small"
            icon={<EyeOutlined />}
            onClick={() => onView(record)}
            className="active-press"
          >
            详情
          </Button>
        )}
        {onEdit && (
          <Button
            type="link"
            size="small"
            icon={<EditOutlined />}
            disabled={!canEdit}
            onClick={() => onEdit(record)}
            className="active-press"
          >
            编辑
          </Button>
        )}
        {onDelete && (

            title={deleteConfirmTitle}
            description={deleteConfirmDescription}
            onConfirm={() => onDelete(record)}
            okText="确定"
            cancelText="取消"

            <Button
              type="link"
              size="small"
              danger
              icon={<DeleteOutlined />}
              disabled={!canDelete || deleteLoading}
              className="active-press"
            >
              删除
            </Button>
          </Popconfirm>
        )}
      </Space>
    ),
  };
}

export function downloadBlob(blob, filename) {
  const url = URL.createObjectURL(blob);

## 六、关于模板化的风险说明与替代方案

### 6.1 为什么 ManagementPageTemplate 风险高

1. **Props 膨胀**：管理页面差异点多（筛选配置、统计卡片、权限控制、特殊交互），统一模板需要 20+ props
2. **业务例外多**：Dorm 页面有"Grid/List 切换"和"床位详情"，Account 页面有"Tab 切换"
3. **模板长洞（Slots）过多**：Header 区、Stats 区、Toolbar 区、Table 区、Modal 区均需定制，模板变成空壳

### 6.2 更稳的替代路径

**阶段一（P0 完成后）**：统一 hooks 层

- `useTableState` + `useTableFetch` + `createBuildTableParams` + `filterUtils`
- 这一层是纯逻辑，无 UI 耦合，可安全复用

**阶段二（P1）**：UI 做布局容器 + Slots

- 创建 `<ManagementPageLayout>` 仅提供布局骨架
- 使用 children / render props 传入自定义内容
- 不强制 props 契约，各页面自由组合

```jsx
// 示例用法
<ManagementPageLayout
  statsSlot={<StatsCards stats={derivedStats} />}
  toolbarSlot={<FilterToolbar ... />}
  tableSlot={<ResponsiveDataView ... />}
/>
```

**准入条件**（P2 评估点）：

- ≥3 个页面同构且差异点可配置化时，才考虑提取完整模板
- 模板 props 控制在 10 个以内
- 每个 slot 的默认实现覆盖 ≥80% 场景

## 八、工程守护（防止复发）

### 8.1 ESLint 规则

> [!WARNING]
> **补强点F：`max-lines-per-function` vs `max-lines`**
>
> - `max-lines-per-function` 限制的是**单个函数**行数，不是文件行数
> - 可能出现：文件 2000 行但每个函数都 <800 行，lint 不报警
> - 正确做法：同时配置 `max-lines`（文件级）+ `max-lines-per-function`（函数级）
> - 或使用 CI 脚本检查 `pages/` 下文件行数

```javascript
// .eslintrc.js 新增
module.exports = {
  rules: {
    // 🔧 补强点F：使用 max-lines 限制文件行数
    "max-lines": [
      "warn",
      { max: 500, skipBlankLines: true, skipComments: true },
    ],
    "max-lines-per-function": [
      "warn",
      { max: 300, skipBlankLines: true, skipComments: true },
    ],
  },
  overrides: [
    {
      files: ["src/pages/**/*.jsx"],
      rules: {
        // pages 文件行数限制（目标 ≤800 行，暂设 1000 行以兼容过渡期）
        "max-lines": [
          "error",
          { max: 1000, skipBlankLines: true, skipComments: true },
        ],
        "max-lines-per-function": ["error", { max: 500 }],
      },
    },
  ],
};
```

**可选 CI 脚本**（更精确的行数检查）：

```bash
# scripts/check-page-size.sh
#!/bin/bash
MAX_LINES=800
for file in src/pages/*.jsx; do
  lines=$(wc -l < "$file")
  if [ "$lines" -gt "$MAX_LINES" ]; then
    echo "❌ $file has $lines lines (max: $MAX_LINES)"
    exit 1
  fi
done
echo "✅ All page files within $MAX_LINES lines"
```

### 8.2 目录约束规范

创建 `frontend-architecture-guidelines.md`，核心要点：

1. **pages/** 仅放页面入口，单文件 ≤800 行
2. **hooks/** 所有可复用逻辑必须封装为 hook
3. **utils/** 纯函数工具，无 React 依赖
4. **components/common/** 通用 UI 组件，必须有 props 类型声明
5. **constants/** 所有配置常量（filterKeys、defaultColumns 等）
6. **Barrel Export 规则**：每个目录有 `index.js` 统一导出

### 8.4 选择语义约定（补强点D）

| 场景             | 触发条件                        | 处理方式                                                   |
| ---------------- | ------------------------------- | ---------------------------------------------------------- |
| 筛选/搜索变化    | `applyFilters()` / `resetAll()` | 清空 `selectedIds`，重置 `selectAcrossPages=false`         |
| 翻页/排序变化    | `handleTableChange()`           | **不清空** 当页选择，跨页选择保持原语义                    |
| 跨页选择         | `selectAcrossPages=true`        | `selectedIds=[]` 表示"选中全部符合条件的结果"              |
| 排除模式（可选） | 需额外实现                      | 增加 `excludedIds` 状态，`selectedIds` 存储被取消选择的 ID |
