# 后端架构对比与功能对齐报告 (Node.js vs Go)

本报告对原 Node.js 后端与由新 Go 后端（Gin + GORM）进行了深度分析对比，旨在列出当前 Go 后端需要修复的问题以及尚未实现的功能。

---

## 1. 项目结构对比

| 特性         | Node.js 后端 (Legacy)                  | Go 后端 (Modern)                                         | 备注                                 |
| :----------- | :------------------------------------- | :------------------------------------------------------- | :----------------------------------- |
| **框架**     | Express.js                             | Gin                                                      | Go 性能更优                          |
| **ORM**      | Prisma                                 | GORM                                                     | 查询实现方式有所不同                 |
| **项目布局** | `src/routes`, `src/services`, `src/db` | `internal/router`, `controller`, `service`, `repository` | Go 采用了更标准的 Clean Architecture |
| **配置文件** | `src/config.js` + `.env`               | `.env`                                                   |                                      |
| **静态文件** | `express.static`                       | `r.Static`                                               | 功能对齐                             |

## 待修复的问题与功能建议清单

虽然核心功能已大部分对齐，但根据代码审查，仍存在以下需要注意或后续微调的点：

1.  **数据一致性 (Upsert 模式):** ✅ **已修复**

    - ~~Go 后端使用的 GORM 默认是软删除 (`DeletedAt`)~~ 经审查，Go 后端模型实际上**没有使用**软删除，两端都是物理删除。
    - 真正的问题是：创建具有唯一约束字段（如 `studentNo`、`employeeNo`）的记录时，如果存在相同标识的记录会产生唯一约束冲突。
    - **解决方案：** 已为 `StudentService.CreateStudent` 和 `TeacherService.Create` 添加 Upsert 逻辑，在创建前检查是否存在相同学号/工号，存在则更新而非创建。

2.  **错误处理响应结构:** ✅ **已修复**

    - ~~Node.js 有时返回 `{ message: "...", detail: "..." }`，Go 某些 Controller 返回 `{ error: "..." }`~~
    - **解决方案：** 已将 Go 后端所有 Controller 和 Middleware 中的 `"error":` 统一替换为 `"message":`，现在与前端 `api.js` 的错误解析逻辑完全兼容。

3.  **统计数据延迟/缓存:** ✅ **已实现**

    - ~~`Dashboard` 的 `summary` 统计在 Go 端是实时计算的~~
    - **解决方案：** 已为 `DashboardService` 添加内存缓存机制（TTL 60 秒），使用 `sync.RWMutex` 保证线程安全。高并发场景下数据库查询压力显著降低。
    - 新增 `InvalidateCache()` 方法，可在数据变更时主动刷新缓存。

4.  **文件处理限制:** ✅ **已实现**

    - ~~Go 的 `UploadFile` 在 `upload_controller.go` 中实现的相对简单~~
    - **已实现功能：**
      - MIME 类型白名单验证（从文件头读取真实类型）
      - 扩展名验证（.jpg, .jpeg, .png, .gif, .webp, .bmp）
      - 文件大小限制（单张最大 10MB）
      - 批量上传接口 `/uploads/batch`（最多 10 张）
      - 错误消息详细描述

5.  **导入逻辑的严谨性:** ✅ **已优化**

    - ~~目前 Go 端的导入是单条处理，报错即跳过或记录失败~~
    - **已实现优化：**
      - 新增 `StudentService.BatchImport()` 和 `TeacherService.BatchImport()` 方法
      - 所有导入记录在**单一数据库事务**中处理
      - 先收集所有有效记录，再批量提交，减少事务开销
      - 失败的记录会被计数但不会中断整个导入过程

6.  **路由兼容性补丁:** ✅ **已重构**

    - ~~目前在 `router.go` 中有较多闭包形式的路由补丁（如 `authMe`）~~
    - **已完成重构：**
      - 将 `authMe` 闭包迁移到 `AuthController.GetMe()` 方法
      - 将登出闭包迁移到 `AuthController.Logout()` 方法
      - `router.go` 现在只包含路由声明，不再包含业务逻辑
      - 减少了约 70 行路由文件代码

---

**核对结论：** Go 后端已基本达到功能平替，核心业务逻辑（Check-in, Task, Permission, Audit）均已按照 Node.js 逻辑重新实现并进行了结构对齐。
